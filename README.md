# RAG-система на основе LangChain для базы знаний 1С

## 1. Обзор проекта

Этот проект реализует систему Retrieval Augmented Generation (RAG) с использованием Python и библиотеки LangChain. Его основная цель — предоставить интерфейс для Вопросов и Ответов (Q&A) по базе знаний, связанной с программными продуктами 1С (например, УНФ, БП, ERP). Пользователи могут задавать вопросы на естественном языке, и система будет извлекать релевантную информацию из проиндексированных документов (PDFs, Markdown-файлы, таблицы Excel и базы данных SQLite) и генерировать ответ вместе с ссылками на источники.

**Ключевые технологии:**
*   **LangChain:** Основной фреймворк для построения RAG-конвейера.
*   **Python:** Язык программирования.
*   **Модели OpenAI / Hugging Face:** Для создания текстовых эмбеддингов и генерации текста.
*   **ChromaDB:** Векторное хранилище для хранения и извлечения эмбеддингов документов.
*   **FastAPI:** Для создания бэкенд API.
*   **Streamlit:** Для создания пользовательского веб-интерфейса.
*   **Различные загрузчики документов:** Для данных из PDF, Markdown, Excel и SQLite.

## 3. Шаг 1: Подготовка и настройка проекта

1.  **Создайте папку проекта:**
    Создайте основную директорию для вашего проекта (например, `my_1c_rag_project`). Все последующие файлы и папки будут находиться внутри этой директории.

2.  **Создайте структуру папок для данных:**
    *   Внутри основной папки проекта создайте директорию `data`.
    *   **Папки конфигураций/разделов 1С:** Непосредственно внутри `data` создайте папки для каждой конфигурации или раздела 1С, по которым вы хотите организовать и фильтровать данные. Например:
        *   `data/УНФ`
        *   `data/БП`
        *   `data/ERP`
        *   `data/Розница`
        *   `data/ЗУП`
        Эти имена папок будут использоваться как значение метаданных `1c_section`.
    *   **Папки типов данных:** Внутри *каждой* созданной папки конфигурации (например, `data/УНФ/`) создайте подпапки для различных типов файлов:
        *   `pdfs/` (для PDF-файлов)
        *   `markdown/` (для Markdown-файлов)
        *   `excel/` (для Excel-файлов)
        *   `faq/` (для JSON-файлов с Q&A)
    *   **Папка для баз данных:** Создайте отдельную папку `data/database/` для хранения файлов баз данных, таких как SQLite.

### 3.1 Импорт FAQ-файлов общего назначения

Если у вас есть общий JSON-файл с вопросами и ответами по разным конфигурациям 1С (например, файл `its_faq.json`), вы можете положить его в папку:

```
data/faq_import/
```

При следующем запуске скрипта `index_data.py`, этот файл будет автоматически обработан:
- Вопросы будут разбиты по конфигурациям 1С на основе поля `"program"`
- Каждая группа будет сохранена как отдельный `.json` файл в соответствующую папку `data/УНФ/faq/`, `data/БП/faq/` и т.д.
- Исходный файл будет удалён после успешной обработки

Формат входного JSON-файла:
```json
[
  {
    "program": "1С:БП",
    "section": "Налоги",
    "questions": [
      {
        "question": "Как начисляется НДС?",
        "answer": "Через документ 'Реализация'."
      }
      // ...
    ]
  }
  // ...
]
```

## 5. Шаг 3: Индексация данных

1.  **Проверьте конфигурации в `index_data.py`:** (Остается таким же)
    *   Убедитесь, что `BASE_DATA_DIR` указывает на `data`.
    *   Скрипт автоматически определяет папки конфигураций.
    *   Подтвердите ваш выбор модели для эмбеддингов и API-ключей.

2.  **Запустите скрипт индексации:**
    Убедитесь, что ваше виртуальное окружение активировано.
    ```bash
    python index_data.py
    ```

3.  **Что происходит во время индексации:** (Остается таким же, но теперь учитывает новую структуру)
    *   Скрипт просканирует каждую папку конфигурации (например, `data/УНФ`, `data/БП`) внутри `BASE_DATA_DIR`.
    *   Внутри каждой папки конфигурации он будет искать подпапки для типов данных (`pdfs`, `markdown`, `excel`).
    *   Он загрузит документы, извлечет текст и назначит метаданные (`1c_section` будет именем папки конфигурации).
    *   Текст будет разделен на чанки и преобразован в векторные эмбеддинги.
    *   Эмбеддинги и метаданные будут сохранены в ChromaDB в директории `db_chroma`.

## 6. Шаг 4: Запуск API и Пользовательского Интерфейса (UI)

### 🚀 Быстрый запуск с помощью `start_rag.command`

Если вы используете macOS, вы можете запускать всю систему одной командой:

```bash
./utils/start_rag.command
```

Этот скрипт:
- автоматически активирует виртуальное окружение,
- завершает запущенные процессы FastAPI и статики (если есть),
- запускает:
  - FastAPI API (`main_api.py`) на порту `8000`,
  - сервер раздачи статики (`serve_static_files.py`) на порту `8600`,
  - Streamlit UI (`app_ui.py`) на порту `8502`.

После запуска UI откроется автоматически.

> ❗ Убедитесь, что файлы `main_api.py`, `serve_static_files.py`, `app_ui.py` и `start_rag.command` находятся в проекте.

## 📄 Раздача PDF, Excel и Markdown-файлов

### Почему это нужно?

При отображении источников в UI к каждому файлу может прилагаться ссылка, например:  
```
📄 [Открыть PDF](http://localhost:8600/pdfs/УНФ/Файл.pdf)
```

Чтобы по этим ссылкам можно было перейти и открыть документ, нужно запустить **дополнительный сервер раздачи статики**.

---

### 🚀 Запуск сервера статики

1. Убедитесь, что в проекте есть файл `serve_static_files.py` (уже должен быть в репозитории).
2. Убедитесь, что в `app_ui.py` указан правильный порт:
   ```python
   STATIC_SERVER_HOST = "http://localhost:8600"
   ```
3. Запускайте проект командой:

   ```bash
   ./utils/start_rag.command
   ```

   Этот скрипт:
   - запускает FastAPI на порту 8000 (для API),
   - запускает Streamlit UI на 8502,
   - запускает сервер статики на 8600.

---

### 🔗 Что делает сервер статики?

Он автоматически монтирует подпапки из `data/`:

| Папка в `data/`                     | URL для доступа           |
|------------------------------------|---------------------------|
| `data/УНФ/pdfs`                    | `http://localhost:8600/pdfs/УНФ/` |
| `data/БП/markdown`                | `http://localhost:8600/markdown/БП/` |
| `data/ЗУП/excel`                   | `http://localhost:8600/excel/ЗУП/` |
| ...                                | ...                       |

---

### 📝 Пример в UI

```python
if source.get("file_name") and source.get("source_type") == "pdf":
    file_url = f"{STATIC_SERVER_HOST}/pdfs/{section}/{source['file_name']}"
    st.markdown(f"📄 [Открыть PDF файл]({file_url})")
```

---

### 🛑 Если не запускать сервер статики

Ссылки на файлы будут вести в никуда. В браузере отобразится ошибка "Connection refused" или "404 Not Found".
```

Перед использованием пользовательского интерфейса необходимо сначала проиндексировать данные (Шаг 3) и запустить API сервер.

### 1. Запуск FastAPI API сервера:

*   Убедитесь, что ваше виртуальное окружение активировано (`source .venv/bin/activate` или `.venv\Scripts\activate`).
*   В **отдельном терминале**, из корневой папки проекта, выполните команду:
    ```bash
    uvicorn main_api:app --reload --port 8000
    ```
    *   `--reload`: включает автоматическую перезагрузку сервера при изменениях в коде (удобно для разработки).
    *   `--port 8000`: указывает порт, на котором будет работать API.
*   API сервер должен оставаться запущенным в этом терминале, пока вы используете пользовательский интерфейс.
*   Вы можете получить доступ к автоматически сгенерированной документации API (Swagger UI) по адресу `http://127.0.0.1:8000/docs` в вашем браузере.

### 2. Запуск Streamlit UI:

*   Убедитесь, что ваше виртуальное окружение активировано.
*   В **еще одном отдельном терминале**, из корневой папки проекта, выполните команду:
    ```bash
    streamlit run app_ui.py
    ```
*   Streamlit обычно автоматически открывает пользовательский интерфейс в вашем веб-браузере. Если нет, он предоставит локальный URL (обычно `http://localhost:8501`), который вы можете открыть вручную.
*   Пользовательский интерфейс будет взаимодействовать с API сервером, запущенным на предыдущем шаге.

## 8. Шаг 6: Оценка и итерация

(Этот раздел остается таким же, как в предыдущей версии README, так как принципы оценки не изменились. Нумерация шагов сдвинулась.)

Создание хорошей RAG-системы — это итеративный процесс. Критически оценивайте результаты:
*   **Точность ответа**
*   **Релевантность источников**
*   **Корректность фильтра**
*   **Галлюцинации LLM**
*   **Качество извлечения текста**
*   **Оптимальность чанков**

**Если результаты неудовлетворительны, рассмотрите возможность изменения:**
*   **Загрузчики документов**
*   **Стратегия разбиения на чанки**
*   **Модели эмбеддингов** (не забудьте переиндексировать)
*   **Настройки ретривера** (`k`, `search_type`)
*   **Модель/Температура LLM**
*   **Тип цепочки (Chain Type)**
*   **Инженерия промптов (Prompt Engineering)**

**Переиндексируйте ваши данные (`python index_data.py`) всякий раз, когда вы меняете шаги предварительной обработки данных, стратегии разбиения на чанки или модель эмбеддингов.**
