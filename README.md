# RAG-система на основе LangChain для базы знаний 1С

## 1. Обзор проекта

Этот проект реализует систему Retrieval Augmented Generation (RAG) с использованием Python и библиотеки LangChain. Его основная цель — предоставить интерфейс для Вопросов и Ответов (Q&A) по базе знаний, связанной с программными продуктами 1С (например, УНФ, БП, ERP). Пользователи могут задавать вопросы на естественном языке, и система будет извлекать релевантную информацию из проиндексированных документов и генерировать ответ.

**Новое в этой версии:** Добавлена поддержка **ансамблевого поиска**, который комбинирует результаты семантического поиска, TF-IDF и полнотекстового поиска (FTS5) для повышения релевантности и точности извлекаемых документов.

**Ключевые технологии:**
*   **LangChain:** Основной фреймворк для построения RAG-конвейера.
*   **Python:** Язык программирования.
*   **Модели OpenAI / Hugging Face:** Для создания текстовых эмбеддингов и генерации текста.
*   **ChromaDB:** Векторное хранилище для семантического поиска.
*   **SQLite (FTS5):** Для полнотекстового поиска по содержимому документов.
*   **Scikit-learn:** Для TF-IDF векторизации.
*   **FastAPI:** Для создания бэкенд API.
*   **Streamlit:** Для создания пользовательского веб-интерфейса (опционально, не является частью основного API).
*   **PyTest:** Для юнит- и интеграционного тестирования.
*   **Различные загрузчики документов:** Для данных из PDF, Markdown, Excel и SQLite.

## 2. Функциональность

*   **Загрузка и обработка документов:** Поддержка различных форматов (PDF, Markdown, Excel, JSON FAQ).
*   **Индексация данных:**
    *   **Семантический поиск:** Создание векторных эмбеддингов (OpenAI или Hugging Face) и сохранение в ChromaDB.
    *   **TF-IDF:** Генерация TF-IDF векторов и модели, сохранение с использованием `joblib`.
    *   **Полнотекстовый поиск (FTS):** Индексация контента документов в SQLite с использованием FTS5.
*   **Стандартный RAG-поиск:** Ответы генерируются LLM на основе документов, найденных семантическим поиском в ChromaDB.
*   **Ансамблевый поиск (Ensemble Search):**
    *   Комбинирует результаты из трех источников:
        1.  Семантический поиск (ChromaDB).
        2.  Поиск по TF-IDF.
        3.  Полнотекстовый поиск (SQLite FTS5).
    *   **Нормализация очков:** Результаты каждого поисковика нормализуются по шкале Min-Max.
    *   **Слияние результатов:**
        *   **Пересечение (Intersection):** По умолчанию, для итогового ранжирования рассматриваются только документы, найденные *всеми* тремя методами.
        *   **Fallback-стратегия:** Если количество общих документов меньше заданного порога (`min_intersection_results`), система может откатиться к использованию только результатов семантического поиска.
        *   **Взвешивание:** Применяются настраиваемые веса к нормализованным очкам каждого метода для расчета итогового агрегированного балла.
    *   **Фильтрация:**
        *   **До слияния:** Семантический поиск поддерживает фильтрацию по метаданным (например, по разделу 1С) до извлечения результатов.
        *   **После слияния:** Результаты ансамблевого поиска могут быть дополнительно отфильтрованы по метаданным.
*   **API:**
    *   Эндпоинт `/query/` для стандартного RAG-поиска.
    *   Эндпоинт `/ensemble_query/` для ансамблевого поиска с гибкой настройкой весов, количества извлекаемых документов и фильтров.
*   **CLI (Интерфейс командной строки):**
    *   `query_data.py` позволяет выполнять как стандартные RAG-запросы, так и ансамблевые запросы с различными параметрами.
*   **Тестирование:** Юнит-тесты для логики ансамблирования и функций поиска, интеграционные тесты для API.

## 5. Индексация данных (`index_data.py`)

Перед первым использованием системы необходимо проиндексировать ваши данные.

1.  **Проверьте конфигурации в `index_data.py`:**
    *   `BASE_DATA_DIR`: Должен указывать на вашу папку с данными (по умолчанию `data`).
    *   `SQLITE_DB_PATH`: Путь к файлу SQLite базы данных (например, `data/database/1c_knowledge_base.db`).
    *   `CHROMA_PERSIST_DIR`: Директория для хранения ChromaDB и артефактов TF-IDF (например, `db_chroma`).
    *   Настройте использование OpenAI или HuggingFace эмбеддингов.

2.  **Запустите скрипт индексации:**
    ```bash
    python index_data.py
    ```

3.  **Что происходит во время индексации:**
    *   **Сканирование и загрузка:** Скрипт сканирует папки конфигураций в `BASE_DATA_DIR`, загружает документы (PDF, MD, Excel, FAQ JSON).
    *   **Обработка и чанкинг:** Текст из документов извлекается и разбивается на чанки.
    *   **Семантическая индексация:** Для каждого чанка генерируются векторные эмбеддинги, которые сохраняются в ChromaDB в директории, указанной `CHROMA_PERSIST_DIR`.
    *   **TF-IDF индексация:**
        *   Создается TF-IDF векторизатор на основе всего текстового контента.
        *   Модель векторизатора сохраняется в `tfidf_model.joblib` внутри `CHROMA_PERSIST_DIR`.
        *   TF-IDF векторы для всех документов и их идентификаторы сохраняются в `tfidf_vectors_and_ids.joblib` внутри `CHROMA_PERSIST_DIR`.
    *   **FTS5 индексация (SQLite):**
        *   Контент каждого чанка (вместе с уникальным идентификатором) индексируется в SQLite базе данных (путь `SQLITE_DB_PATH`) с использованием виртуальной таблицы FTS5 для быстрого полнотекстового поиска.

## 6. Использование API (`main_api.py`)

API предоставляет два основных эндпоинта для выполнения запросов. Запустите API сервер:
```bash
uvicorn main_api:app --reload --port 8000
```
Документация API (Swagger UI) доступна по адресу `http://127.0.0.1:8000/docs`.

### Эндпоинт `/query/` (Стандартный RAG)

*   **Метод:** `POST`
*   **URL:** `/query/`
*   **Тело запроса (JSON):**
    ```json
    {
        "query": "Ваш вопрос здесь",
        "section": "УНФ"
    }
    ```
    *   `query` (str): Текст вашего вопроса.
    *   `section` (str, опционально): Раздел 1С для фильтрации (например, "УНФ", "БП"). Если не указан или "все", поиск будет по всем разделам.
*   **Ответ (JSON):** Структура `QueryResponse` (см. Pydantic модели в `main_api.py`) с полями `answer` и `sources`.

### Эндпоинт `/ensemble_query/` (Ансамблевый поиск)

*   **Метод:** `POST`
*   **URL:** `/ensemble_query/`
*   **Тело запроса (JSON):** `EnsembleQueryRequest`
    ```json
    {
        "query": "Ваш вопрос для ансамбля",
        "top_k": 5,
        "top_n_individual": 7,
        "weights": {
            "semantic": 0.6,
            "tfidf": 0.2,
            "fts": 0.2
        },
        "section": "УНФ",
        "filter_after_merge": {
            "source_type": "pdf",
            "1c_section": "УНФ"
        }
    }
    ```
    *   `query` (str): Текст вопроса.
    *   `top_k` (int, опционально, default: 10): Количество финальных результатов после слияния.
    *   `top_n_individual` (int, опционально, default: 10): Количество результатов, извлекаемых каждым индивидуальным методом поиска (semantic, TF-IDF, FTS) перед слиянием.
    *   `weights` (Dict[str, float], опционально): Словарь с весами для каждого типа поиска. Пример: `{"semantic": 0.5, "tfidf": 0.3, "fts": 0.2}`. Если не указан, используются веса по умолчанию.
    *   `section` (str, опционально, default: "все"): Фильтр по разделу 1С, применяемый *только* к семантическому поиску (до слияния).
    *   `filter_after_merge` (Dict[str, str], опционально): Словарь для фильтрации результатов *после* слияния и агрегации. Ключи - имена полей метаданных, значения - ожидаемые значения.
*   **Пример запроса `curl`:**
    ```bash
    curl -X POST "http://127.0.0.1:8000/ensemble_query/" \
    -H "Content-Type: application/json" \
    -d '{
        "query": "настройка резервного копирования",
        "top_k": 3,
        "weights": {"semantic": 0.6, "tfidf": 0.2, "fts": 0.2},
        "section": "УНФ",
        "filter_after_merge": {"source_type": "pdf"}
    }'
    ```
*   **Ответ (JSON):** Такая же структура `QueryResponse`, как и для `/query/`. Поле `answer` будет содержать информацию о том, что это результаты ансамблевого поиска. В метаданных каждого источника (`SourceDocument`) оценка от ансамбля временно добавляется в начало `content_snippet` в формате `[Score: X.XXXX]`.

## 7. Использование CLI (`query_data.py`)

Скрипт `query_data.py` позволяет выполнять запросы из командной строки.

### Стандартный RAG-запрос:
```bash
python query_data.py "Ваш вопрос?" [--section ИМЯ_РАЗДЕЛА]
```
Пример:
```bash
python query_data.py "Как настроить резервное копирование в УНФ?" --section УНФ
```

### Ансамблевый поиск через CLI:
Для активации ансамблевого поиска используется флаг `--ensemble`.

```bash
python query_data.py "Ваш вопрос?" --ensemble \
  [--weights '{"semantic": 0.5, "tfidf": 0.3, "fts": 0.2}'] \
  [--top_n_individual 10] \
  [--top_k_ensemble 5] \
  [--section РАЗДЕЛ_ДЛЯ_СЕМАНТИКИ] \
  [--filter_after_merge_json '{"meta_ключ": "meta_значение"}']
```
*   `--ensemble`: Включает режим ансамблевого поиска.
*   `--weights 'JSON_СТРОКА'`: Позволяет задать веса для каждого метода в формате JSON.
*   `--top_n_individual ЧИСЛО`: Количество документов от каждого поисковика до слияния.
*   `--top_k_ensemble ЧИСЛО`: Финальное количество документов после слияния.
*   `--section РАЗДЕЛ`: Фильтр по разделу для семантического поиска (аналогично RAG).
*   `--filter_after_merge_json 'JSON_СТРОКА'`: JSON-строка для фильтрации результатов после слияния по метаданным.

Пример ансамблевого запроса:
```bash
python query_data.py "Резервное копирование УНФ" --ensemble \
--weights '{"semantic":0.6,"tfidf":0.2,"fts":0.2}' \
--top_n_individual 7 --top_k_ensemble 3 \
--filter_after_merge_json '{"1c_section": "УНФ"}'
```

*   **Расположение тестов:** Директория `tests/`.

*   **Запуск тестов:**
